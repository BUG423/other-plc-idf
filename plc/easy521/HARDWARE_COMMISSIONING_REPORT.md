## 2. 我是如何完成工程的

1. 安装和使用汇川官方 AutoShop V4.11.0.5，使用其附带的 H5U USB 设备驱动建立 USB 连接。没有把 Windows 的普通串口枚举成功当作 PLC 编程通信成功；以 AutoShop 的连接测试为准。
2. 先从真机上传原工程，保留原有 MAIN 梯形图及配置。原备份的 MAIN 是 X0 常闭触点驱动 Y0 的逻辑。初始只读阶段没有覆盖；用户后续授权且确认负载隔离后，按第 8 节下载 DEV。旧工程备份未被更改。
3. 新建独立 `BESS_E521_DEV` 工程，系列/型号选 Easy500 / Easy521，语言选 LiteST；创建 `FB_BESS_AdaptiveSupervisor_Easy521` 和实例 `fbBESS`。
4. 从软件导出真实变量表模板，按 AutoShop 原生列名生成导入文件。全局变量导入 19 项，功能块变量导入 58 项，使用 BOOL / INT / REAL。全局网络公开属性为“私有”，没有擅自暴露控制使能位。
5. AutoShop 4.11 的 Unicode 原生 CSV 使用 UTF-16 编码；已保存工作区 UTF-8 导入清单，实际导入前转换为 UTF-16。功能块接口、内部状态和正文均经过真实编译检查。
6. 将已有 Easy521 控制正文及 MAIN 调用正文导入工程，没有为了得到通过结果改变储能公式、阈值或状态更新逻辑。正式 MAIN 只调用一次功能块并发布其输出，启动使能和测量有效位均为 FALSE。
7. 在“程序块属性”中勾选恒定扫描周期，设为 5 ms；看门狗设为 100 ms，保存并重新打开工程确认设置仍存在。这是开发配置，看门狗余量仍须真机测量。
8. 通过“工程另存为”建立 `BESS_E521_TEST`，只替换测试工程的 MAIN，保留同一个储能功能块。两份原生 `.FB` 文件 SHA-256 完全相同：

   `0a9d9836c86594f2954a30432cbf3de745296f3ea2d2bc5ec9ee8e8f1ad3afdd`

9. 测试 MAIN 每次主扫描调用功能块一次；每组先复位，再逐扫描施加输入并比较固定期望值，最后将结果写入模拟器 D 寄存器。生成器及两份正/负对照源码已归档。测试正文为 880 行，未超过厂家单个 LiteST 文本 1000 行的限制。
10. 启动 AutoShop 明确标示为“离线调试”的厂商模拟器，通信目标切换为本机 127.0.0.1，而非 USB 真机。本节模拟器阶段的“下载成功”和“运行命令”记录均发生在模拟器中；后续物理 USB 下载另列第 8 节。
11. 使用只支持 FC03 读取、固定目的地址为 `127.0.0.1:502` 的脚本读回结果。脚本先确认 AutoShop 打开的是 TEST 工程并处于离线调试，再确认端口属于官方 `Simulator/h5u_daemon.exe`，才发送读取请求。没有用这个脚本写任何寄存器。
12. 验收完成后退出模拟器，恢复打开正式 DEV 工程，并按完整目录复制两份原生工程。归档时逐文件比较 Windows 原件与工作区副本 SHA-256，均一致。正式工程 86 个文件，测试工程 145 个文件；编译缓存不应被当成用户源码。

测试断言初版编译遇到语法错误，后将容差写为十进制 `0.000002` 并将长表达式拆行，最终编译为 0 错误。两项格式同时调整，未单独隔离原因，因此不据此推断厂商全面禁止科学计数法。储能功能块本身未因此修改。

## 5. 必须区分的限制和逻辑细节

- **扫描配置不是实测周期。** 厂家第 67 页说明，执行超过设定周期时按实际执行时间扫描。本次模拟器状态栏约为 15～16 ms，并非 5 ms；其版本显示为 6.11.0.0，与 USB 真机查询的 6.11.0.1 区分记录。厂家第 731 页明确 Windows 模拟器不是实时系统，CPU/内存显示也是 PC 指标。
- **10 次调用不自动等于现场 50 ms。** 只有真机调用周期实际为 5 ms 时才可作该换算；无效帧或禁用会冻结计数，真实经过时间会延长。
- **无功饱和锁存不是严格的连续 10 次判定。** 原 Python/SLX 的计数条件成立时加 1，不成立时减 1，而非立即清零；第 27 组验证了该语义。连续 10 次满足一定可触发，但间断序列也可能累计触发。若现场要求严格连续 10 次，需另行确认并修改需求/算法，不能声称现有逻辑已经满足。
- **Ready 只表示控制器已初始化。** 输入无效时已初始化的 Ready 可以仍为 TRUE；不能拿 Ready 单独替代通信健康或设备安全许可。
- **安全有效位不自动筛掉 NaN/Inf。** 本次验证了 `xInputValid=FALSE` 的归零和状态冻结；尚未实现或验证通信层拒绝 NaN/Inf、半帧和越界数据。不得把这项测试描述为这些异常报文已被真机拦截。
- **当前是控制算法工程，不是完整现场应用。** 正式工程的测量量、指令及许可位尚未绑定实际通信/软元件；没有实现客户/服务器角色、整帧发布、心跳、超时和重连。原 double64 协议与目标 REAL32 协议也尚未在通信两端联调。
- Python 6 秒闭环采用 BESS 等效动态与简化馈线关系，厂商模拟器跑的是固定控制输入，不是完整 IEEE 33 节点 Simulink 电气网络 HIL。
- `BESS_E521_TEST` 是模拟器专用，包含自动施加输入和测试寄存器写入，**禁止向物理 PLC 下载**。新建 `BESS_E521_BENCH` 只用于已确认隔离的硬件台架，禁止现场投运；DEV 已下载不表示已完成接口或投运安全验收。

## 6. 真机部署前仍需的信息与验收

1. 用户已明确授权覆盖，且对“已隔离，可以真机测试”的确认请求回复“可”，本次按隔离已确认继续。测试期间必须维持该隔离；当前需用户检查物理 RUN/STOP 开关和指示灯，不能把软件 RUN 请求失败描述为程序已运行。
2. 确定七项量测来自 Simulink/PC、仪表、PCS 或 BMS，以及各设备的 Modbus 角色、IP/端口/站号、地址与浮点格式。
3. 完成非阻塞通信、整帧快照、数据有效性、心跳、超时归零、重连和设备本地超时保护；零指令计算成功不等于变流器已经收到零值。
4. DEV 已加载但仍 STOP；待解决启动问题后，在隔离台架执行 BENCH 固定向量，读回完成标识及逐组结果，测试后恢复禁用 DEV。再测量实际周期与执行时间；有限样本的最大观察值不能等同形式化最坏执行时间。
5. 再做断线、坏帧、NaN/Inf、掉电/热启动、设备拒绝指令及联锁故障注入，最后进行 SIL/HIL 和受控现场验收。
