# Easy521 面板 Y0 输出指示灯闪烁台架示例

本目录只提供 [MAIN 正文](MAIN_body.st)，用于现有 Easy521 厂商工程的独立工作副本。不新增全局变量、任务或定时器，不修改旧内存探针、原工程或历史证据。**它实际命令物理输出 Y0，只有在用户明确确认所有输出已与负载断开后，统筹才可进入下载步骤。** 24 V 已接通、CPU 报 RUN 或交付本文件，均不能代替这项现场事实。

## 官方手册已核对的行为

本机 AutoShop 附带的官方 PDF 中所引页面已核对。页码为从 1 开始的 PDF 页码，与所引印刷页码一致。本段来自离线手册核对，后续真机结果单列。

| 文档与页码 | 已确认的内容 |
|---|---|
| 用户手册 U137 | IN/OUT 黄绿色状态灯表示对应输入/输出是否有效；RUN 灯表示用户程序运行，与 Y0 灯不同 |
| U141，Easy52X 输出规格 | 输出处于驱动状态时，对应输出指示灯亮，且注明由软件控制 |
| U151 | Y0 对应 I/O 端子 B1，输出公共端 COM 为 B9；不是上方 24 V 电源端子 |
| 编程手册 P168；指令手册 I27 | `M8013` 为只读 BOOL 的 1 秒周期振荡时钟；`M8002` 为用户程序开始运行的第一个周期标志 |
| P248–249；I28 | X/Y/M 可直接用于文本程序；Y 为 BOOL 输出软元件；支持 `:=` 赋值和 `IF…ELSE…END_IF` |
| P90 | RUN 扫描程序并刷新 Y 输出，STOP 停止程序扫描及 Y 输出 |

因此，本机面板对应 Y0 的输出状态灯可作为**不接外部负载的可视目标**。无需为观察板载灯另接电灯、电阻或短接 Y0/COM；本示例不要求改动输出接线。它没有测量端子电压、电流或带载能力，面板亮灭不能替代这些验收。TN/TP 分别是 NPN/PNP 输出，外接负载接法不同，不能拿本目录作为外部接线方案。

## 源码、周期与初值

```iecst
IF M8002 THEN
    Y0 := FALSE;
ELSE
    Y0 := M8013;
END_IF;
```

本轮实际编译源码文件的SHA-256为`6c51789d485457f9fc64ff34c2f0101f6c10db61bce1bd2a0f529c2c0111e7ed`。源码后续若修改，应以新构建和部署记录重新关联。

文件只含正文，不包 `PROGRAM`、`VAR`、`CONFIGURATION` 或 `TASK`。沿用现有 MAIN 任务：历史 DEV 是名义 5 ms 配置，现场须重新核对；本目录不声称测得了 5 ms 周期。

首次 RUN 扫描将 Y0 命令置为 FALSE，之后每次扫描跟随 M8013。手册确认的是**完整振荡周期 1 秒**，不是“亮 1 秒再灭 1 秒”。所引手册没有规定精确占空比、上电相位或 RUN 重新开始时钟相位，因此不把每半周固定 500 ms、第一眼一定先灭等写成已验证行为。第一扫描的低电平仅持续一个任务扫描，不是人眼可见的起动延时。

STOP 后正文不再执行；预期控制器按 P90 停止 Y 输出，面板 Y0 不再按此程序闪烁。正文没有在 STOP 时运行的清零分支；Y 软元件影像是否保留、灯是否熄灭、外部电压如何变化，要分别观察，不能通过当前源码推成已完成或安全认证。遇到强制输出、轴/PWM 占用、其他任务或中断写 Y0，也不能只靠 MAIN 这几行排除冲突。

## 给统筹的编译与现场验收建议

1. **事实确认。** 在计划中记录本次准确设备身份、24 V 供电、物理开关状态，以及用户对所有输出空置/负载隔离的明确答复；先按手册和设备丝印定位 Y0 对应的 OUT 状态灯。不能把 PWR/RUN/ETH 灯当作本例心跳。用户未确认负载隔离时，仅做离线/工作副本准备。
2. **工作副本。** 保留当前设备应用、工程和恢复材料；使用新的明确工程路径，仅替换 MAIN 正文。检查 Y0 没有其他程序写入、在线强制、脉冲/轴输出映射；不改任务、I/O、网络、FB 或全局分配。遗留 POU 可以保留，但本 MAIN 不调用它们。
3. **完整厂商编译。** 走现有厂商工程同步/F7 核验流程，要求 MAIN 读回与此源一致、编译日志新鲜且零错误、必需 ARM/组合产物新生成，并保存完整 build record、源 SHA-256 和文件闭包。这包含直接软元件预处理：当前 `prepare_vendor_st.py` 会拒绝 Y0/M8013 等软元件，不能用该受限独立对象工具替代完整工程编译；Linux LLD 成功也不能算本例编译/打包通过。
4. **有授权与事实后才下载。** 完整工程下载会替换设备应用，不能描述为“只写一盏灯”。使用已核验厂商路径，保存传输日志和独立程序一致性结果；F8/校验导致的文件漂移按已有严格追溯记录，不覆盖原 build 或猜测字节一致。未知结果不重放下载。
5. **观察与计时。** 记录实际 CPU 状态后，观察面板 Y0 至少 10 个周期，可让用户拍摄约 15 秒视频并说明具体是哪一盏灯。分别记录光学亮灭、实际 CPU 状态、在线 M8013/Y0（若可读）及源码/构建身份，不能仅因存在 USB 或数值变化就构造在线成功。计时只是台架现象，不作为硬实时或带载性能结论。
6. **STOP 与收尾。** 经统筹当前授权的操作路径切 STOP，并独立确认模式与灯停止闪烁；不以灯灭单独推断 STOP 成功。随后按已约定的恢复方案结束。本例不是储能控制程序，不能遗留接入负载投运。
