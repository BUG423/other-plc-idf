# 从本机工具链判断去 Windows 的切入点

日期：2026-10-17。用户补充目标：研究绕过 AutoShop 的原生控制路径，产品不局限 Easy521。本页只读取本机安装文件和已有工程产物；未运行厂商 EXE/DLL、操作 AutoShop、切换 USB 所有权或访问 PLC。原始文件保留原地，公开仓库只保存观察结果与哈希，不复制厂商库或接口文档。

## 1. 本次新增证据

完整来源、SHA-256、`file/readelf` 命令及输出见 [本机工具链台账](20261017-local-toolchain-inspection.json)。

| 观察 | 可确定的事情 | 尚不能确定的事情 |
|---|---|---|
| `Bin/STLang{,_New}/StLang.exe`、`Kernel.dll` 为 Windows PE32；`Bin/ld.lld.exe` 也为 PE32 | 本机现有 ST 前端及链接工具的宿主平台依赖 Windows | 不能据此断言厂商没有 Linux 版本，或这些功能无法独立实现 |
| `SysLib{,_New}/ARM/` 中三个 `.o` 为 ARM ELF32/EABI5 | 厂商安装包已有标准 ELF 形式的目标库，值得拆开编译、链接与应用包装三个阶段研究 | ELF 是可识别格式，不表示外部 ABI、运行时加载、包校验或授权已经解决 |
| 本轮工作副本 `STTemp/MAIN.o` 有 36 个不同名字的未定义全局/弱符号；三库定义可按名字覆盖其中 2 个 | 即使工具能处理 ARM ELF，仍有变量布局和外部函数等依赖要明确 | 名字相同不是参数类型、调用约定或执行语义兼容证明；未定义符号在可重定位文件中也不等于构建失败 |
| `Temp/stprog.o` 仍有 82 个不同名字的未定义全局/弱符号 | 链接后产物仍可能依赖运行时或后续处理阶段；需要解释真实加载契约 | 不根据符号数量判断优劣，也不将它当作独立可执行固件 |
| 本机 InoLoaderPro 附带接口说明提及 Linux 与 Windows 库版本 | 可将“获取厂商 Linux 烧录 SDK”列为具体问询项，可能先替换传输层 | 未拿到对应 Linux 主库，未证明该接口支持 Easy521 应用工程、上载或运行控制；系统固件烧录与应用下载分别验证 |
| 同目录的 `libIvtAes.so` 是 Linux x86-64 库；未发现对应 Linux 主控制库 | `.so` 扩展名不是设备固件证据；该文件是宿主侧资产线索 | 不能从它推断 Easy521 使用 x86，也不能据文档中 Linux 字样推断设备运行 Linux |
| 安装目录现有升级样本名称属于 H1/H2/H3 等系列，未找到 Easy521 系统镜像 | 不能从这些其他型号样本认定 Easy521 的芯片、分区或恢复方法 | 未完成对所有磁盘或厂商资源的穷尽搜索 |

附带接口文档未收入仓库，也不转抄其函数、结构或人员信息；台账只登记原路径、哈希及高层存在性观察。

## 2. 如何继续取得芯片与控制证据

芯片识别宜交叉印证：匹配型号/硬件修订的官方固件和板级资料；用户可提供的断电板卡丝印；有电气规格与接线依据的启动日志；经授权接口读取的 CPU/设备树信息。历史 `sunxi_usb_udc` 自述只能作为候选平台线索；USB 字符串可由软件配置，见 [Linux 官方 gadget 文档](https://docs.kernel.org/usb/gadget_configfs.html)。

识别 CPU 后，还要确认 I/O 经 GPIO、串行总线、协处理器还是 FPGA 连接，以及看门狗、输出提交和保持数据规则。这里列的是待查项，并不声明 Easy521 已确认具有某种协处理器。能启动系统、能加载应用、能控制端子和满足周期要求应分别验收。

保留厂商运行时的路线可以先研究应用 ABI 与编程协议，不必等拿到完整 BSP；替换系统固件的路线才必须补齐启动、内存、驱动和可恢复性。对于不同厂商/型号，分别维护兼容性与证据矩阵，共享上层工程和命令面，见 [多目标 ADR](../../architecture/ADR-0002-native-multitarget.md)。

## 3. 立即可推进的研究顺序

1. 将 ST 前端、ARM 链接、工程包装、应用部署分开，建立最小源变更与产物差分集；先解释依赖，再谈替换。
2. 用 Linux 原生链接器对已有 `.o` 做有界离线实验，结果仅作为链接阶段证据。LLVM 官方说明 LLD 支持 ARM 和跨目标链接，不能据此直接宣布 Easy521 编译链完成。[LLVM LLD](https://lld.llvm.org/)
3. 查明厂商 Linux 烧录主库的正常获取方式、支持型号、版本与用途；本次只形成问询项，未联系厂商。
4. 同步在自控 Linux 目标上验证开放 ST 编译/执行/变量追踪，让完全无 Windows 的工作流不依赖单个私有型号研究成功。

本轮仍未确认 Easy521 的准确 SoC、OS、板级 I/O 或系统镜像结构，也没有产生可向 PLC 下载的新原生产物。
