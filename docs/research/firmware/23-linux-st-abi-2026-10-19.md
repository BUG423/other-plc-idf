# Linux 自写 ST 内存探针到 ARM 对象：限定前端与局部 ABI 对照

2026-10-19。本轮首次用独立的 Linux 前端，把明确限定的 ST 正文转成 LLVM IR，再由本机原有 LLVM 20.1.2 `llc` 真正编译出新的 ARM 可重定位对象。`+1`、`+2`、`+32767` 三种源码得到不同对象；同一 IR 另编为 x86 对象后真实执行，45 个样本含有符号边界均符合本探针规定的行为。已有厂商对象只在编译完成后用于局部 ABI 比较，没有被复制或作为代码生成输入。工具为 [compile_easy521_native_probe.py](../../../tools/compile_easy521_native_probe.py)，逐项元数据在 [JSON](23-linux-st-abi-2026-10-19.json)。

**这是一条真实的、范围极窄的 source→ARM object 新链路，尚不是 Easy521 原生 Linux 编译器或完整应用。** 当前没有合法的 COUNTER 地址/保持区/任务绑定，没有完整包、下装或 ARM 执行；结果恒为 `runtime_abi_verified=false,arm_code_executed=false,downloadable=false`。本轮没有 Windows、GUI、网络或 PLC 操作，也未改变当前设备程序。

## 1. 支持的源码合同

固定 profile 为 `counter-dint-increment-v1`，只接受一个 `COUNTER:DINT` 外部变量，以及一条完整的赋值语句；增量为十进制正整数 1～32767。允许大小写和已有词法器支持的嵌套注释，但必须消费整个正文；第二条语句、未知尾随文本、IF、TON、库调用、其他名称、直接 I/O、类型化数字和字符串均拒绝。它是独立实现的受限前端，不借助 MatIEC 或厂商编译器悄悄扩展支持范围。

`body.st`：

```iecst
(* 纯内存探针。每次调用 MAIN 计作一次扫描，增量单位为计数/扫描。
   任务周期、初值和保持属性尚未分配；没有物理 I/O 或设备副作用。
   此研究 profile 明确定义 32 位回绕，尚不代替完整厂商语言语义。 *)
COUNTER := COUNTER + 1;
```

显式 `globals.json` 沿用既有中间输入准备工具的 schema：

```json
{"schema":"plcidf.vendor-main-source.v1","globals":{"COUNTER":"DINT"}}
```

编译入口只把这两个文件和显式的受信任本机 `llc` 当作输入。变量名称、类型、初值、保持状态和周期的缺口不会靠参考对象补齐。外部符号是 `COUNTER`，其真实内存归属未知；它不能被传给目前只支持既有八项变量的绑定器冒充已分配全局。

## 2. 为什么没有直接套用现有 MatIEC C

现有 MatIEC→GCC 路径已经验证 Linux 电脑上的 ST 扫描与监控，但该路径为程序结构、访问标志和本地调度器生成 C，并不自动对应厂商 POU 的外部符号和任务 ABI。本机原有工具中有 GNU 主机 GCC、LLVM `llc`，没有可调用的本机 Clang 或 ARM GCC C 前端。因此本轮选择明确限制语言表面，独立解析为 LLVM IR，再调用现有 ARM 后端；没有把本地 Linux 程序对象改名成 Easy521 对象。

生成的 IR 声明 `COUNTER` 为外部 32 位存储，`MAIN` 为无参数、无异常的函数；每次调用执行一次 volatile load、32 位 add、volatile store。`add` 没有 `nsw/nuw` 标志，当前 profile 的边界行为定义为模 2³² 回绕。这是探针合同，不是对其他厂商运算、故障位、异常或编译选项的推定。[LLVM IR 运算语义](https://llvm.org/docs/LangRef.html#add-instruction)及 [llc 静态编译接口](https://llvm.org/docs/CommandGuide/llc.html)是后端使用依据。

ARM 目标固定为 `thumbv7-none-eabi`，特性固定为 `+v7,+thumb2,+vfp3,+neon,+reserve-r9`，采用 soft float、静态重定位、对象输出和 `-O=2`。这些值由被观察厂商对象的属性指导，不能据此确认实际 Easy521 芯片型号、操作系统或完整运行时 ABI。

## 3. 与自写厂商探针的局部对照

参考来自 [研究 11](11-plain-main-object-2026-10-18.md)保留的自写 `COUNTER := COUNTER + 1/2;` 厂商对象。新前端不读取参考路径；研究比较另行打开参考文件并复核哈希。

| 局部项 | 厂商参考 | 本轮新对象 | 可支持的结论 |
|---|---|---|---|
| 格式 | ELF32 little-endian ARM EABI5 REL | 相同 | 目标对象格式相容 |
| 指令与属性 | ARMv7 Application、Thumb-2、VFPv3、NEON、R9 unused | 已观察参考标签均相同；额外 speed 优化标签 | 属性接近，不证明全 ABI |
| MAIN | 全局 Thumb 函数；简单探针不读取传入参数 | 全局 Thumb 函数，无参数 void 返回 | 相同入口形状；任务调用方未核实 |
| COUNTER | UND 外部符号；MOVW/MOVT 地址重定位后 32 位读写 | 相同重定位类别与 32 位读写 | 局部全局访问形状相同 |
| 加法 | 符号扩展到 r0/r1，与 r2/r3 常数调用 `_ST_INT64_ADD`，只存回 r0 | 直接 32 位加法，无运行库调用 | 低 32 位运算可比较，不要求机器码相同 |
| 异常/调试元数据 | 有 unwind helper 和调试节 | `nounwind`，只保留 cantunwind 形状，无调试信息 | 有意差异，未宣称逐字节相同 |

冻结 `_SysLib.o` SHA-256 为 `2fde5706b01135ac15db5f17b6847dd361894c909ecaa6a3cf9cca2f132782d2`。其中 `_ST_INT64_ADD` 的 Thumb 符号值 `0x39`，实际 `.text+0x38` 的 6 字节局部函数仅执行 `adds r0,r0,r2; adcs r1,r3; bx lr`，没有内存写或其他调用。这支持当前单 DINT 加法取低 32 位的局部算术对照；没有由此推出完整运行时无副作用或设备运行兼容。

原厂 `+1` 对象 SHA-256 `9d2063daa05318c463c27a43ae6895e79fe27ba6d34dadd08dc27eb0e22affd1`，`+2` 为 `ef27685da39c95eedb3c942d64b2a3ee78ade4d50ce7897d73041213bf26add4`。旧编译器身份与其真实编译来源仍在研究 11；本轮只读取参考，不执行旧编译器。厂商原始文件、完整反汇编和库不进入仓库。

私有根目录为 `.plcidf/research-23-native-st-20261019/`。下表目录均已生成且不再覆盖；每项有原文、声明、IR、对象及 `probe-report.json`。

| ST 增量 | 目录 | ARM 对象 / MAIN 长度 | ARM 对象 SHA-256 |
|---|---|---|---|
| +1 | `verified-plus1/` | 732 / 16 B | `f09450c622d93eb3189594d28762aea73696807013051ef47e618c3818bcc00e` |
| +2 | `verified-plus2/` | 732 / 16 B | `50c39b9bf7717b22c9cb1fff7d74cead09fac2a05cd2dbce51dd7bb6b522bd57` |
| +32767 | `verified-plus32767/` | 736 / 20 B | `70ba5a1b8b2a3b26ddbb08c34764182a0e18a2eda865c5568f0c5c3cf30aaf79` |

实际编译器为原有 Linux `llc`，176,944 B，SHA-256 `994d679339b301a81bcc969d475bc1082da1cbfae40b2f3da9421cc85324a6d3`。动态后端 `/usr/lib/x86_64-linux-gnu/libLLVM.so.20.1`，143,545,784 B，SHA-256 `4b93481bd1c9d42c0951275dd275d4a9d30db78c309ae2cc0405669bc6dbbf8a`。工具复核 llc 主文件及三个 Python 前端/解析组件的哈希；动态库身份另列于本研究 JSON，没有声称工具冻结并校验整个系统动态依赖闭包。

同一 IR 另编译为 x86 主机对象，用 GCC 连接一个只提供 `int32_t COUNTER` 存储和三次 MAIN 调用的自写 harness。初值分别为 `INT32_MIN,-1,0,41,INT32_MAX`，每种增量获得 15 个实测样本，总计 45 个。例：从 `2147483647` 开始，+1 后为 `-2147483648`，+2 后为 `-2147483647`；这验证的是同一 IR 的主机执行。没有 ARM 模拟器或真机执行证据，相关标记继续为 false。

初次对象结构校验因 LLVM 自动附带的 unwind 外部符号而失败，原目录 `plus{1,2,32767}-build/` 原样保留；之后明确声明纯内存函数 `nounwind`。另有早期未保留 R9 的中间产物也保留，新 profile 固定 `reserve-r9`。失败及迭代没有改写为成功。

## 5. 可重跑命令与边界检查

使用本轮已有源文件重编译，但必须换一个全新输出目录：

```bash
.venv/bin/python tools/compile_easy521_native_probe.py \
  --source .plcidf/research-23-native-st-20261019/plus1.st \
  --globals .plcidf/research-23-native-st-20261019/plus1.json \
  --llc .plcidf/research-tools/llvm20/extracted/usr/lib/llvm-20/bin/llc \
  --output-dir .plcidf/research-23-native-st-fresh-build
```

工具每个子进程默认 10 秒、允许 0.1～30 秒，只运行一次，不使用 shell、不重试。输出目录独占创建；冻结输入/IR 和成功对象设为只读。编译后复核原输入、冻结文件、llc 和前端组件；拒绝源码/IR 漂移、非 ARM 或非 EABI5 对象、非 Thumb MAIN、额外外部 helper、未知重定位类别和诊断。失败保留已经创建的目录与报告，不复用失败对象。

```bash
PLCIDF_TEST_LLC="$PWD/.plcidf/research-tools/llvm20/extracted/usr/lib/llvm-20/bin/llc" \
  .venv/bin/python -m unittest discover -s tools/tests \
  -p test_compile_easy521_native_probe.py -v
```

本轮 **18 项测试通过，0 跳过**，其中 4 项真实 LLVM 测试：三个源规则生成不同 ARM 对象；同 IR 主机执行及回绕；真实编译后源码/IR 漂移拒绝；改变架构/EABI/外部符号拒绝。其他负例覆盖完整语法拒绝、错误声明、字符串/截断注释、已存在目录、符号链接、两个阶段的超时不重放、零退出码但诊断非空，以及非 Linux 编译器拒绝。未提供 `PLCIDF_TEST_LLC` 时，4 项真实 LLVM 测试明确跳过，不能将其报告为真编译通过。

下一步可以将新的 ARM 对象与明确选定的冻结运行库做离线链接，保留 source→IR→POU→link 全链哈希；链接成功也只能表示对象组合成立。仍需独立解决合法变量/保持区/任务分配、完整厂商 ABI、应用配置/FOID、下载会话、设备字节校验与真机执行，才能接入用户所需的纯 Linux 全流程。
