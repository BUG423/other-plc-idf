# 44. 原厂清程序与恢复入口的离线核查（2026-10-19）

本轮确认原厂存在 `ClearAppCommand`，但它仍使用与 SetGCM 相同的运行时协议，未发现可据此绕过当前无响应通信链的证据。另有手册明确说明的 Easy52X USB 固件烧录和 TF 卡启动下载路径；本轮未操作这些路径，也未证明故障设备能进入对应模式。来源、文件哈希及局部代码范围哈希见[配套 JSON](44-offline-recovery-interfaces-2026-10-19.json)。没有修改工具代码、执行 Windows 程序或访问设备。

## 清程序仍经过运行时通信

已核对真实 H530 调用链：`InterfaceMgr RVA 0x68d10 → virtual +0xd8 → H530 RVA 0x56e0`，其中安装 `CClearAppCommand` 虚表 `0x79924`，执行项 `+0x3c` 指向 `0xc230`。`0xc24f` 随后调用通用 `0xc7d0`，最终通过已绑定 protocol 的 `+0x2c` 发送 selector=1、operation=2；SetGCM 也使用这条通用发送链。

该入口向通用函数传入本地索引 `0xff000100`、一个零字节和 `normalflag=0`，仍有符号/地址解析，不能将常量直接当成已恢复的字面线上请求。AutoShop 自身在连接、权限和界面检查后，于 RVA `0x11ffd0f` 调用该 facade，并非独立启动恢复入口。即使“清程序”在正常连接下可用，也没有证据表明它在 GCM 和文件读取均不回复时仍可用。本轮未实现或发送它。

`SimpleCommand` 也不能根据名称理解为 CPU 复位：真实链为 facade `0x69290 → virtual +0x128 → H530 0x62d0 → CSimpleCommand 0x304e0 → 0x30510`。枚举 0 经通用 `0xc7d0` 向 `0xff000010` 写 DWORD 1；非零枚举经 `0xc6c0` 读取同一位置。AutoShop 先传入 0，再以 `0x7b` 进入读取分支，最多观察 200 次。结合[报告14](14-easy521-download-paths-2026-10-18.md)中下载文件控制/状态的命名证据，这是下载文件辅助事务，不能把 `0x7b` 理解为“复位命令123”。Simulator 的名称仅作旁证，没有据此发送真机请求。

`CControlCommand` 在 `0xcbe0–0xcc19` 也通过已绑定 protocol 的 `+0x2c` 发请求。已检查的 facade 导出和具体发送链没有建立独立的 CPUReset、reset-communication 或恢复通道；这是有限范围的未发现结论，不代表固件不存在其它机制。

## 手册提供的其它路径及现有缺口

现有离线编程手册文本共 1022 页，与[早期报告01](01-manual-facts.md)所用版本页码不同，本轮按当前文本定位：

| 路径 | 原厂资料 | 应用影响与条件 |
|---|---|---|
| USB 固件烧录 | 第990页，§29.2.1 | 明确包含 Easy52X，且其烧录文件与 Easy30X/32X/50X 分开。顺序为 PLC 断电、打开 AutoShop 固件烧录、选择厂商匹配文件、重插 USB 后由厂商界面识别确认。完成后删除原应用。 |
| USB/以太网固件升级 | 第998页，§29.2.3 | Easy 支持两种通信方式，完成后保留原应用；不能据此认定无响应运行时仍可升级。 |
| TF 卡用户程序下载 | Easy 用户手册第131页明确第6章为 Easy52X；第161–162页 §6.6.2 | 通过存储扩展卡，在上电时读取 `PLCProgram` 中匹配机型/口令的 Down/Updown；第176页列出 B 槽 `GE20-TF` 和 `GE20-TF-RTC`。用户尚无相应扩展卡与下载文件证据。 |
| TF 卡固件烧录 | Easy 用户手册第162页，§6.6.3 | 需要匹配的厂商镜像及存储扩展路径，烧录后删除应用与用户数据。 |

上述 USB 固件烧录是值得继续向厂商核实的文档入口，但还缺匹配 Easy52X 镜像、实际启动模式的 USB 身份/握手以及本机进入该模式的证据。已备份的 17 个应用文件不能充作系统固件或 Down/Updown 文件。通用编程手册中的 MFK 与数码管操作也不能外推为 Easy521 面板恢复步骤。

安装的 InoLoaderPro 默认 USB 配置为 `0483:5710`，与实测运行时 `0471:a531` 不同；产品信息表中的通用 PLC 类别不能证明其支持本机恢复。不能修改 VID/PID、套用其它型号镜像来补足这项证据。

## 验证与剩余问题

本轮仅核对原厂 PE 导出、RTTI/虚表、局部反汇编和现有手册文本，四项虚表关联断言及来源/代码段哈希复核通过。没有新增设备操作、恢复写入或写重试。实际 CPU 错误码仍未知；当前运行时通信是否可在实体 STOP 与完整断电后恢复，以及厂商独立烧录通道能否服务该故障，继续分别验收。
