# Easy521：ELF差分与故障阶段边界（2026-10-19）

本轮仅离线比较原机正常备份、失败候选和研究40修正版的两个ARM对象，没有修改编译代码、重新构建、访问设备或执行Git操作。**除研究40撤销的外部对齐假设外，尚未找到第二项能明确解释故障的装载约束违规；物理异常码与确切故障阶段仍未知。**结构与来源哈希见[43 JSON](43-elf-loader-boundaries-2026-10-19.json)。

| 核对项 | 三套对象的实际结果 | 结论边界 |
| --- | --- | --- |
| ELF与入口 | ELF32 LE、ARM、ET_REL、ident一致，最终flags均`0x05000200`；MAIN都是global STT_FUNC、Thumb位为1且在可执行text内 | 没有发现入口缺失或越界；不是运行证明 |
| MAIN长度 | 原机108 B；失败版52 B；40版112 B | SBR和库随当前text重定位，不能把旧offset用于新对象 |
| GOT与重定位 | 没有新增GOT节/相关reloc；新对象的reloc类型全部存在于原机 | 未发现新增不支持类型的证据 |
| UND/SInfo | runtime函数导入没有新增；增加既有Pcmd type8变量，移除`_HC_INTERRUPTFCBYST` | 参考loader有type8变量回调；实际调度语义仍未验证，不强改ABS |
| 库与元数据 | 原机43个STCLib函数逐字匹配New分支，9个SysLib函数相同；继承的symbol/vars/userprog与原机一致 | 不支持换旧库或盲改symbol WORD5为3 |

已检查的Simulator loader按SHF_ALLOC映射节，额外非分配 `.comment/.llvm_addrsig` 未在该参考路径显示为拒绝原因。它不是Easy521固件，不能由此保证物理loader接受所有新布局。

失败MAIN第一条就是 `VMOV.F32`，早于外部VLDR。40版虽已将外部访问改为严格字节搬运，仍执行寄存器浮点运算。匹配VFP属性、以及正常LED文件内未必被调用的浮点库函数，不能证明物理FPU可用或任务上下文正确。因此不能把当前故障确定为对齐，也不能宣称40版已经消除了所有执行风险。恢复基线之后，如需进一步区分，可先离线构建并反汇编确认一个无VFP指令的常量REAL标记，再单独决定是否作受控比较；本轮没有构建或执行它。

协调者的最新通信证据必须分别表述：冷启动后故障数量读取为OUT22成功、IN超时；Windows原厂libusb0 GCM单读为claim成功、OUT18、IN返回`-116`；另一次文件健康读取为OUT返回`-7`、0字节，**没有进行IN调用**。不能概括成“所有OUT成功”。这些结果说明不能只归因于WSL，但USB描述符/控制层仍可用不等于应用协议服务健康。现有SDK不含Easy521固件启动链，无法证明应用装载发生在通信服务启动之前。

17文件精确回读证明存储字节，不证明模块已装载、调度或执行。原机恢复、40修正版和失败版应分别关联；ACK、文件哈希或冷重启都不自动提升运行状态。

本机《Easy系列可编程逻辑控制器用户手册》的Easy52X专章给出的可操作边界为：

- PDF137页：实体RUN/STOP开关控制主机运行/停止。当前实体STOP是否明确完成仍待用户确认；不能从模糊语音推定。
- PDF138页：故障重启须关闭24V并拔除USB供电，PWR熄灭至少10秒后再上电。明确STOP位置后，可由协调者决定一次有界只读观察；手册未在此保证能绕过损坏应用装载或恢复通信。
- PDF161页：在STOP状态写程序。
- PDF162页6.6.2：TF用户程序下载需要TF存储扩展卡、≤32GB FAT32卡、AutoShop生成且机型/密码匹配的Down/Updown，置于`PLCProgram`目录；上电复制成功后进入STOP。它是独立的用户程序传输路径，不能直接用17个ELF/FOID代替下载包。用户是否具备所需扩展硬件未知，不能当作已经可用的恢复入口。

本轮没有恢复出可在当前无响应状态调用的清除、复位、BOOT或固件擦写合同，不建议以猜测命令替代故障定位，也没有建议固件擦写。
