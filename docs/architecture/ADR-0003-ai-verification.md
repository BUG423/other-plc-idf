# ADR-0003：AI 编程以可执行的需求场景作为反馈

状态：本地实现与验收通过，待合并；2026-10-17。关联 [T13/#17](https://github.com/BUG423/other-plc-idf/issues/17)、[ADR-0002](ADR-0002-native-multitarget.md)。

用户希望在 WSL 的对话终端完成 PLC 编程，不再手动把 AI 返回的代码复制进 Windows 软件。现有开放后端已经真实编译并执行 ST，但固定的计数器/心跳观测只能证明工具链可运行，不能证明启停、联锁、定时器等控制要求得到实现。

从控制器的工作方式出发，每次扫描读取输入映像、执行程序并更新状态与输出。软件阶段可把需求写成有序输入序列与逐步输出期望，在确定的扫描时刻执行真实生成代码。因此本轮优先补齐输入契约、扫描场景、断言与可追溯报告；自然语言需求仍由当前终端 AI 理解和编写，无需另建聊天服务或绑定模型供应商。

## 接口与职责

1. `plcidf.json` 声明源码、固定编译器、周期、类型化 `signals.inputs/outputs`。当前 I/O provider 为 memory-only。
2. `main.st` 包含实际控制逻辑和单任务配置。MatIEC 负责 ST 语法与语义，工程检查器只验证受限结构契约。
3. `scenarios.json` 声明输入变化、持续扫描次数和该步骤结束时的输出期望。每个场景独立初始化，步骤之间保留程序状态与输入。
4. `verification.py` 预校验场景，调用真实 build/deploy/replay，比较实际值与期望，并绑定输入与产物哈希。
5. C runner 执行生成的 `config_init__/config_run__`。实时运行沿用 monotonic 调度；场景执行使用虚拟 IEC 时间，第一扫描为 0，随后每扫描增加声明的周期。控制逻辑与计时器均来自编译后的 ST。
6. CLI `verify --json` 提供单次反馈，生成工程附带 `AGENTS.md` 告知 AI 如何编辑、验证和报告。

## 约束与失败语义

类型范围由共享契约校验；写入仅针对声明的输入，期望仅针对声明的输出。BOOL 不接受整数替代，数值必须有限，REAL 可声明绝对容差。大小写冲突、未知字段、空验收、越界类型和超量扫描明确拒绝。

构建沿用源码、生成 C、运行器、工具链、ELF 和部署包校验。replay 只运行当前 state_dir 已部署的 release，绑定 run_id 与程序身份，并以外部期限结束不返回的扫描。输入文件在检查、构建和场景结束时再次核对；输入改变使报告失效。编译通过与场景通过分别报告，任一必需步骤失败则整体失败。

AI 可以根据失败定位修改代码，但不能为了让错误实现通过而擅自改变原验收期望。需求变化时，说明规则变化，再更新相关代码与场景。场景集的覆盖度仍需要审查；通过有限场景不能证明任意控制逻辑完全正确。

## 验证等级

确定扫描验证逻辑与声明的 IEC 时间行为，不测量 Linux 的调度抖动、物理信号电平、现场总线、掉电保持或设备故障输出。已有 `run/monitor/stop` 用于本地实际进程观测。两种执行都不表示 Easy521 运行了开放程序。

Easy521 适配需要独立的方言映射、厂商编译/下载通道与设备端证据。以后新增目标时可复用场景规范，但须在该目标执行并比较结果，不能沿用 Linux 的通过结论。
