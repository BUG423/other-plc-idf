# ADR-0005：Easy521 的 AI 编程、部署与现场反馈闭环

日期：2026-10-19。状态：接受作为实施方向；反馈示例已交付，严格 Linux 原生与 Easy521 运行闭环待验收。

## 背景

用户希望在 Linux 终端内完成“描述需求→AI 改 ST→编译下装→运行数据与人工观察→再改”。现有能力分布在 Easy521 厂商工程桥接、Windows 无 GUI 对象编译、Linux D 区访问和 `open-linux` 真实 ST 执行中。这些能力都有效，但不能合并成尚未发生的 Easy521 全闭环。

[ADR-0002](ADR-0002-native-multitarget.md) 区分目标 runtime/BSP，[ADR-0003](ADR-0003-ai-verification.md) 规定 AI 与独立验收的关系，[ADR-0004](ADR-0004-vendor-build-release.md) 已拆开构建意图、本地候选、厂商比较和设备字节。新需求补足每次迭代的身份关联及人工观察。

## 决定

### 复用既有工具，增加观察记录

现有 AI 编码终端负责理解需求与编辑文件，不新建聊天服务或绑定某个模型供应商。工程配置继续使用现有配置；源码、完整构建、intent、release 继续使用原 schema。新增反馈 schema 只描述观察，不承载连接配置、寄存器映射或设备命令。

一轮由 `iteration_id`、父轮和需求版本关联。保存原始 MAIN 哈希及完整工程输入树哈希，分别引用既有 `build_hash`、`intent_hash`、`release_hash`、动作 ID、样本与证据哈希；未知值明确为 null/unknown，不填假哈希。release 发生厂商重编译时按 ADR-0004 记录转换，不能将后来的哈希改写成原选择内容。

### 观察、身份与结果分开

反馈逐项记录动作、期望、实际、观测时间、记录时间、来源和限制。人工看见灯变化、工具读到变量、厂商比较一致、设备字节读回和 CPU 模式分别是不同证据。用户观察很有价值，也可以与工具不一致；保存双方原始结果，并把差异作为下一轮调查输入。

模型推断不允许标为已观察的通过/失败。反馈文件通过 JSON Schema 只能证明形状正确；不能据此认定所写型号、哈希、在线状态真实，也不能授权执行动作。采集器未来应核对引用文件哈希、动作时间窗和程序/设备身份，再由汇总结果报告各维度质量。

### 明确两阶段终态

过渡方案允许 WSL 调用 Windows 厂商工具，优先利用现有完整工程路径完成 Easy521 行为闭环。无 GUI `StLang` 仅降低交互成本，不满足 Linux 原生要求。

严格 Linux 原生方案需要完整应用编译、链接/包装、传输、CPU 控制和监测都在 Linux 上实现；验收时禁用 Windows 后端，并保存实际工具/进程与设备证据。可以研究 Linux 调用厂商已有应用协议或保留原 runtime，不要求先替换系统固件。若编译依赖不可移植，应明确该阻塞，并继续交付已证实的阶段能力，不能把桥接重命名为原生。

### 每种控制层单独声明能力

应用参数访问、CPU RUN/STOP、新应用下装、系统固件替换分别声明接口、身份、前置条件和验收结果。Modbus D 区操作可以服务既有应用约定；它不承担新应用下载。ARM 对象不是完整 PLC 应用。物理芯片相同也不能推出任务/I/O ABI、存储布局或固件通用。

`open-linux` 为真实可执行的独立验证目标，适合有限语义、注释与验收场景研究。其通过结果保留目标标签，不能跨目标升级为 Easy521 的时间、物理 I/O 或二进制兼容证明。

## 迭代过程与失败处理

| 阶段 | 必须保留的结果 | 不能自动越过的边界 |
|---|---|---|
| 需求与 ST | 需求版本、未决项、源码哈希、注释与规则差异 | AI 不擅自选择未定义的故障/重启语义 |
| 检查与编译 | 诊断、完整输入、目标、工具身份、对象/完整应用的明确范围 | 静态检查或单个对象不能认作可部署完整应用 |
| 候选与下装 | intent、release、动作记录、项目/字节验证等级 | unknown 不能解释成“没发生”，不能自动重放写动作 |
| 运行观察 | 本次设备/程序身份质量、CPU 状态、时间窗和连续样本 | UI 缓存值或历史型号不能当作当前运行证明 |
| 人工反馈与修订 | 观察来源、期望/实际、原始附件哈希、父轮关联 | 测试失败不静默降低原需求；修改期望需记录新的需求版本 |

首个硬件验收保持现有无物理 I/O 探针接口，用规则 +1 与 +2 的可区分行为、停止状态、语法负例证明两个完整迭代。后续真实工艺需求再增加对应物理观察。有限扫描样本只能证明该窗口中的行为，不能宣称长期实时性或功能安全认证。

## 备选与取舍

直接以 D 区写入作为完成终态，不能满足修改任意 ST 的目标，因此只作为参数控制能力。立刻替换系统固件会引入启动、驱动、I/O 和恢复等额外问题，暂不作为闭环前提。只交付 Windows 桥接可较快产生用户价值，但不满足最终 Linux 原生要求，因此保留为独立里程碑。新造统一配置/聊天系统增加迁移成本，当前没有必要。

证据分级会使某些已发生的操作仍返回 unknown，尤其是项目一致但缺设备字节绑定时。这是可解释的限制；保留候选和事实比伪造一个成功状态更有利于后续调试。历史 879/150 软件检查和已有下载记录都保留其范围与日期，不作为当前扫描成功的替代。
