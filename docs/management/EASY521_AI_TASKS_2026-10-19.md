## 有限研究与决策门槛

每个研究批次先写一个问题、已知输入、限定目标版本、拟观察输出和结束条件。以下问题可以并行，不能互相掩盖缺口：

1. **完整应用产物**：从受限 ST 对象继续到任务/全局/库/I/O 绑定和最终包装。验收为输入与输出的完整哈希和可复现转换；只找到对象格式即结束本阶段并列缺项，不能冒充可下装。
2. **传输与提交**：明确确认后哪个文件由谁处理、顺序、校验及提交。验收包含失败/超时后“不重放”的状态记录。没有可信 ABI/协议前停止猜测调用，改为只读分析。
3. **CPU 与程序身份**：找到独立于缓存 UI 值的当前设备/模式/程序标识。先证明查询来自本次设备，再讨论控制。若仅有项目比较，则公开保持 project 等级。
4. **现场反馈**：先用 unknown 示例验证工具可表达未知，再用真实记录检查时间窗、附件、迭代关联与人工/仪器差异。内容真实性由证据核对，JSON 合法不等于事实已核验。

Windows 无 GUI 编译/既有工程是过渡路径；严格 Linux 原生编译与协议是并行研究。系统固件替换另开需 BSP/恢复证明的研究任务，不堵塞本轮应用闭环，也不因读到芯片型号就视为可执行方案。

## 风险与收口

| 风险 | 对应任务与处理 |
|---|---|
| 厂商版本、工程输入或确认后产物变化 | EAI-04/08 固定版本、覆盖完整输入并记录转换；无法绑定则降级为 project/unverified，不改写原候选 |
| UI 缓存或历史连接被误认作当前设备 | EAI-02/05 要求当次来源和时间窗；缺独立身份时保留未知，不用计数值自证在线 |
| 猜测协议、超时后重放导致重复动作 | EAI-04/05/09 先校准 ABI/序列，单次提交；unknown 后转入核对当前状态，不自动再写 |
| 新接口误触物理输出或改变既有任务语义 | EAI-03/07 首轮只用既有内存探针；任何 I/O/任务变更显式列入新需求并另验收 |
| 编译器不可移植、运行库或许可证条件不明 | EAI-08 列出具体不可得组件和分发条件，保留固定版本证据；阶段停止不宣称 Linux 原生完成 |
| 人工观察缺时间/身份或与工具矛盾 | EAI-06 保存 unknown 与双方原始记录；不能用 AI 推断补成实测结论 |

## 交付门禁

| 门禁 | 需要看到的结果 | 失败后的处理 |
|---|---|---|
| G0 合同 | 需求规则、固定接口、身份字段、unknown 语义和反馈 schema | 补具体缺失项；不让 AI 猜需求 |
| G1 可编译候选 | 正例真实编译，负例拒绝，完整输入/产物/工具身份关联 | 保留诊断与旧候选；不继续下装错误产物 |
| G2 单次部署 | intent/release/动作一致，当前项目与设备证据分级 | 可能已改变设备时报告 unknown；不把重试当恢复默认动作 |
| G3 运行与反馈 | 同一轮 CPU/信号采样、人工观察和时间窗有来源 | 保留差异；补只读查询或人工反馈，不自行认定根因 |
| G4 两轮迭代 | +1→反馈→+2 行为可区分，停止与语法负例可解释 | 缺哪级写哪级；软件测试数量不补硬件缺口 |
| G5 严格原生 | Windows 后端关闭后完成 G1～G4 | 仍标过渡完成/原生未完成，不改目标定义 |

若设备当前条件不足以判断，应记录观测事实、风险和下一项可判定实验。额定主电源与过去 USB 条件下 RUN 失败没有建立因果证明，不新增“未接 24V 一律禁止 RUN”规则。实际设备操作由统筹根据当前现场事实和已授权范围协调。
